## 0b. 🔴 THE IDENTITY GATE (the Paradigm lesson, Aug 26)

**A leaderboard/directory NAME is not a vendor IDENTITY.** Before applying anywhere on a third-party ranking's strength: verify the domain the ranker links (Finnrick vendor pages carry a verified-domain line/badge), and check the test/review dates are consistent with the current site's operation. Paradigm's #7 nearly got declined over a federal-conviction name-collision with defunct `paradigmpeptides.com`; Finnrick's "verified this link on 11 Nov 2025" + post-2024 test dates settled it as the new entity's. Both directions of the lesson apply: a good rank may belong to someone else — and a scary history may too.

## 0c. 🔒 FINNRICK POSTURE (Mark, Aug 27)

Finnrick is **citable as an attributed, dated differentiator** (Peptide Partners #1-reta; Paradigm #7 overall) and **linkable as a reader pointer** (the Swiss Chems line) — it is **NOT a placement/delisting input**. Its scores are pass-rates against a ~99.5%-purity + dose-accuracy bar, **not purity percentages** — a "bad" Finnrick score can be 98%+ pure. Never conflate them in copy. PP's model reports each vendor's own published testing; it does not adjudicate a third party's relative scoreboard.

## 0d. 🔒 SELF-SERVICE VETTING ONLY (Mark, Aug 27)

**If a vendor's published COAs and the labs behind them can't carry the verdict, the vendor isn't worth the correspondence.** No emails to ask where COAs live, no chasing a lab's credentials, no requests for lot-numbered certs. The evidence is public or the vendor is skipped.

Consequences, applied Aug 27: **Paramount** (COA search returns "0 results") and **Lumera Labs** (claim-only lab page) → SKIP, closed. Not "B pending an email."

The exception is a **partnership ask**, which is a different animal: writing to a vendor with no visible affiliate program to ask whether one exists is business development, not vetting. Chimera and Chameleon are that case.

## 0e. 🔒 SCREENING RULES — corrected Aug 30, 2026

### 1. AN AGE GATE IS NOT A WALLED CATALOG
🔴 **An age-verification interstitial is normal, expected, and arguably required for this product category. It is NOT the login-wall disqualifier.**

The disqualifier is a catalog that cannot be browsed **without an account** — a login/register form standing between a visitor and the products, with COAs gated behind sign-up. An age gate asks a yes/no question and lets you through.

**How to tell them apart before calling it:** does the page ask you to *confirm something* (age, researcher status) and then admit you, or does it ask you to *become someone* (create an account, sign in)? If a "Continue" or "I am 21+" button reaches the catalog, it is an age gate. If the only path forward is credentials, it is a wall.

⚠️ **This rule exists because it was gotten wrong.** IRON Peptides was called login-walled in Batch 1; it is age-gated. Elite Science Labs (`/` and `/shop/` both redirecting to `/my-account`) is the genuine article. Confirm which one you're looking at before it becomes a verdict.

### 2. A DOMAIN SWARM IS A FLAG, NOT A VERDICT
🔴 **If a search surfaces a cluster of lookalike domains, report it to Mark for investigation. Do not disqualify on it alone.**

Track record: **Apex** — search found a 5-domain cluster; the GoAffPro dashboard then showed the approved domain was `apex-peptides.com`, a **sixth, distinct** domain not in the cluster at all. The search-derived swarm did not describe the vendor. Apex remains unscreened, not disqualified. **Orbitrex** — the cluster was real, but the disqualifying fact was that the program is *pending, not approved*.

**So: the dashboard domain is authoritative. Search can point at the wrong cluster entirely.** A swarm finding means "verify identity harder," and Mark investigates before any verdict rests on it.

### 3. ESTIMATE TRAFFIC AND SITE AGE
Add to every screen, where obtainable without paid tools:
- **Domain age** — registration date via WHOIS/RDAP. A storefront registered weeks ago cannot have the customer base its copy implies, and it is the cheapest tenure check available.
- **Traffic signals** — any public estimate, plus proxies: indexed page count, review volume across platforms, social following and post history, whether the domain appears in third-party rankings.
- ⚠️ **Label these as ESTIMATES.** Third-party traffic numbers are modeled, often wildly off for small sites, and the Orbitrex "117K monthly visits" figure turned out to be an unattributable ledger artifact. Report the number *and* its source, never the number alone.

**Why it matters:** a vendor's traffic is the ceiling on what a listing can earn. A perfect COA library on a site nobody visits is a page that costs more to build than it returns.

## 1. THE VETTING STANDARD

Before a newly-discovered vendor gets a page:

**0. 🔴 CONFIRM THE CODE IS BOUND TO THE AFFILIATE ACCOUNT.** *(Outranks the other five — added Aug 8 2026.)*

A code that applies at checkout proves **nothing** about attribution. Vendors routinely create the code Mark asks for as a **standalone store coupon** and never link it to his affiliate ID — from their side they did exactly what was requested.

Ask the vendor directly: *"Is this code linked to my affiliate account, or is it a standalone store coupon?"* Then verify a coupon shows as **attached** in the portal.

**Confirmed unbound on three vendors: Almighty, Spartan, Ignite.** Almighty ran **589 visits to zero attributed sales** this way. Full signature and per-vendor status in **PP_COMMISSIONS §2**.

⚠️ **A vendor who won't bind the code isn't viable.** Code attribution is PP's proven revenue mechanism — buyers read the code in a search result or an X post and go direct, never touching a link. An unbound code means PP promotes a discount for free.

1. **Site age** — asset upload dates, copyright year, domain registration. Under ~3 months = wait unless something else is compelling.
2. **Independent review footprint** — Trustpilot, PeptideCritic, PeptiPrices, Reddit. Absence isn't disqualifying alone, but it removes the ability to verify anything.
3. **Verifiable US-registered entity + physical address.** A state registration lookup takes two minutes. Naming an LLC beats naming nothing; naming nothing is the strongest single signal.
4. **COA library contents, not its existence.** A `/coas` link proves nothing until a certificate is opened.
5. **Pricing sanity** — dramatically below market on GLP-1s is a known counterfeit signal.

**None of 1–5 is individually disqualifying. Three or more together means wait.** Check 0 is different — it's a hard gate.

### 🔍 THE FOUR DISQUALIFIER PATTERNS

1. **Login-walled catalog — 5 vendors, disqualifying every time.** PP can't price or link what it can't see. Check before anything else.

## 1b-3. 🆕 COMMISSION ≠ CUSTOMER DISCOUNT — a recurring trap

GoAffPro portals show **two different percentages** and they are frequently not equal:

| Vendor | Commission to PP | Discount to buyer |
|---|---|---|
| AMP | 15% | 15% |
| Improved | **20%** | **15%** |
| Valkyrie | **20%** | **10%** |

**Rule: the page states the CUSTOMER discount. The commission never appears anywhere on PP.** Every onboarding prompt must state both explicitly and say which is which.

⚠️ **Valkyrie is the asymmetric case** — pays the most, gives the reader the least. Worth asking them to raise the customer-side discount, since code attribution is where PP's volume actually is.

## 1b-4. 🆕 COUPON CASE — TEST IT, DON'T ASSUME

GoAffPro displays the coupon **lowercase** (`profpeptide`) while the referral parameter is **uppercase**. PP publishes uppercase by convention.

**Verified empirically, twice, in a live cart:**
- **AMP** — Epithalon $45, applied uppercase `PROFPEPTIDE` → *"Coupon code applied successfully"*, **−$6.75 = exactly 15%**
- **Improved** — BPC-157 $65 → *"PROFPEPTIDE applied · −$9.75"*, total $55.25 = **exactly 15%**

**WooCommerce is case-insensitive**, so the lowercase portal display is cosmetic. **Still test each new vendor** — platforms differ, and Improved runs a custom checkout.

⚠️ **Test on a SINGLE unit.** Improved's notice: *"Bundle pricing does not combine with promo codes."* A BOGO cart would have failed the test misleadingly.

## 1b-7. 🆕 A NEW DISQUALIFIER PATTERN — the vendor-controlled QR

**Add to the four patterns in §1b.**

**A verification QR that resolves to the vendor's own site rather than the issuing lab's verifier.**

The QR exists so a buyer can confirm a certificate independently of the vendor. One pointing back at the vendor inverts that entirely — it's a link the seller controls, on a document the seller is asking you to trust.

**Verified-genuine verifiers for comparison:** Chromate at `chromate.org/verify` (Mile High, with a per-cert access code) · Liquilabs at `base.liquilabs.cz` (Particle, per-record) · Freedom Diagnostics search codes at `FreedomDiagnosticsTesting.com` (Improved, per-accession) · Horizon Analytical at `horizonanalytical.com` (Valkyrie).
