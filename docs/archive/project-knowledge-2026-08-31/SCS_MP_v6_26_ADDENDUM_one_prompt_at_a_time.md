# SCS_MP — ADDENDUM: One prompt at a time

**Status:** ACTIVE addendum to SCS_MP v6.25 · **§ PROMPT DELIVERY**
**Date:** August 13, 2026
**Amends:** the "every response to a report ends with the next actionable prompt" rule — supplies the missing half.

---

## 🔒 THE RULE

**One executor report → one prompt. Nothing queued as a pasteable block while that executor is working.**

The existing rule says every response to a CC/CINC/CD report ends with the next actionable prompt. That's correct and stands. What it never said is the inverse: **do not write a prompt when there is no report.**

When Mark raises a topic mid-task — a new idea, an observation, a question about something unrelated — the response is **the queue entry, not a prompt.** The prompt gets written when the executor reports back and the item reaches the top.

---

## Why

Prompts written speculatively pile up in chat. Mark scrolls past three or four pasteable blocks looking for the current one, and the earlier ones either get pasted out of order or silently lost. A prompt that isn't pasted is worse than no prompt — it reads as delivered work that quietly evaporated.

The failure isn't writing too much. It's that **a prompt in the chat log looks like an instruction awaiting action**, and several at once destroys the signal that any single one carries.

> **Recorded Aug 13, 2026.** Over one session Claude wrote prompts for the ion aliases, the hub link-structure analysis, the retired-vendor orphan routes, and the supplements investigation — several while CC was mid-task on something else. Mark asked for them to stop piling up. The existing rule had been read as "always end with a prompt" rather than "end with a prompt when responding to a report."

---

## What to do instead

**While an executor is working:** answer the question, give the analysis, make the recommendation. Then add the item to the queue as a one-line entry.

**The queue lives at the end of a response as a numbered list** — this is already SCS_MP's "queue listed after every prompt." Only the top item becomes a pasteable block, and only when the executor reports.

**Format:**

```
Queued behind the current task, in order:
1. Ion aliases + roster-wide alias cross-check
2. Hub link-structure analysis
3. Survodutide/mazdutide profiles, separate PR
```

Not three code blocks.

---

## The exceptions

**Mark asks for a prompt directly.** "Give me a prompt for X" or "write that up for CC" — write it. He may be routing it to a different tab, or holding it deliberately.

**A different executor is free.** CC being mid-task doesn't block CINC. One prompt per executor, not one prompt total. ⚠️ But say plainly which tab it's for.

**The item is time-boxed and would expire.** A sale ending tonight beats queue order. Say why it's jumping the queue.

---

## What doesn't change

- Every response to a report still ends with the next actionable prompt. Never "say go and I'll write it."
- Still no prompt on a status request, a queue update, a direct question, or anything that isn't reviewing executor output.
- Still never re-send a prompt for work already in flight.
- Still sequence by revenue over queue order.
- Still click-to-copy fenced blocks, always naming the tab.
