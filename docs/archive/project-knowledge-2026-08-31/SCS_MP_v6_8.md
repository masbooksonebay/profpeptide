## 🚦 RULE #0 — VERIFY BEFORE ASSERTING (no guessing) — HIGHEST PRIORITY, GOVERNS ALL OTHER RULES

Never guess, theorize, assume, or reconstruct from memory anything with a knowable correct value — formats, names, codes, discounts, catalog contents, whether a page/file exists, prior decisions, portfolio state.

Check the source FIRST:
1. The relevant ref doc / knowledge file — **after a compaction, re-read it; never trust the summary.**
2. Live data — `web_fetch` / `vendors.ts` / the live page.
3. Fresh web research.

If the source can't be reached, **say the value is unverified rather than filling it in.** When unsure, **stop and check — do not proceed on a hunch.**

This consolidates and hardens the pre-existing #5 (search project knowledge first), #15 (check master ref docs before inventing), and #17 (fresh research). It outranks all of them and applies to every lane (Apps, PP Affiliate, White Label) and every task type — not just X posts.

## 📣 Community-Group Outreach Pattern (v6.7)

Validated via HR's HYROX community push. Studio go-to-market pattern for niche-sport apps:

1. **Join the relevant community groups** (FB groups, forums) for the app's sport/niche — regional + global.
2. **Observe posting norms** before posting — most fitness community groups allow self-project posts but prohibit ticket/commercial sales spam.
3. **DM an admin first** where the group is strict or admin-gated (Emma Waring / HYROX UK pattern).
4. **Post a brief, direct, value-first message** — name the app, describe what it does, offer first-100-free (grandfathered), invite feedback.
5. **Vary + space posts** across groups — identical text to many groups in a short window triggers admin flags.
6. **Nominative trademark framing** — reference the sport/race the app trains *for*, never imply affiliation with the trademark holder.
7. **Link-in-first-comment fallback** if the platform throttles link-in-body reach.

Applies forward to: WN (Olympic weightlifting groups), Cali, CrossFit, and SC (powerlifting forums/groups).
